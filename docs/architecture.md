# 架构与数据流

## 模块职责

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| HTTP 服务 | `app.py` | FastAPI 路由、输入解析和页面入口 |
| 数据模型 | `app.py` / `Order` | 统一保存平台、订单、客户、商品、数量、金额及分类结果 |
| 品类分类 | `classify()` | 使用商品关键词识别品类，返回分值与命中理由 |
| CSV 导入 | `import_csv()` | 解析订单，调用分类，按平台与订单号去重 |
| 复购分析 | `recommendations()` | 聚合客户品类历史，计算周期与排序分 |
| 浏览器端 | `static/` | 总览、搜索、导入与复购清单 |

## 订单输入

必填字段：`order_id`、`customer_id`、`product_name`、`amount`、`ordered_at`。可选字段：`platform`、`quantity`。日期采用 `YYYY-MM-DD`。

平台订单号的唯一性范围是「平台 + 订单号」。重复导入不会创建第二条同键订单；这属于当前订单快照导入逻辑，尚未实现订单状态变更与退款事件的增量同步。

## 分类与复购规则

1. 品类分类对商品名称执行词典匹配；无法匹配时归为「其他」。
2. 复购分析按客户和品类聚合历史购买记录，计算平均购买间隔。
3. 当距上次购买的天数达到对应周期的 65% 后，纳入候选清单。
4. 使用周期临近程度和历史次数生成排序分，提供解释所需的原始字段。

规则分数没有经过概率校准。后续若引入训练模型，应保留这个基线，并通过严格按时间划分的数据比较效果。

## 存储与配置

默认连接为 SQLite，运行后在本地生成 `demo.db`。`DATABASE_URL` 可以切换到 MySQL，具体命令见[使用手册](user-guide.md#数据库)。`.env.example` 用于说明配置；启动时应通过环境变量设置实际值，不能假设示例文件会被自动加载。

仓库保留源码与虚构样例。实际运行数据库、日志和本地配置已被 Git 忽略。
